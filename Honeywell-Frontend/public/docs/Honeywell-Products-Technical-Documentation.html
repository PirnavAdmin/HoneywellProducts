Section 1

1. Project Overview & Monorepo Architecture

The Honeywell Products platform is a full-stack e-commerce and administrative operations system for smart surveillance hardware, solar cameras, NVRs, and perimeter security equipment.

Section 4

4. API Integration & Request-Handling Flow

  • Bearer Token Authorization: Axios and Fetch interceptors attach customerToken (storefront) or adminToken (console) dynamically to requests.
  • Ngrok Tunnel Header: Automatically appends ngrok-skip-browser-warning: true during local development.
  • Swagger Documentation: OpenAPI definitions accessible at /swagger/index.html during backend execution.
Section 5

5. Authentication, RBAC & Session Auto-Lock

  • Storefront Customers: Authenticate via /api/CustomerPortal/login with IDOR ownership verification protecting order records.
  • Admin Console: Sign in with email/ID followed by mandatory 6-digit email OTP 2-Factor Authentication.
  • 30-Minute Idle Auto-Lock: Monitored in AdminLayout.jsx; automatically purges active session credentials and redirects to login when inactive.
  • Dynamic RBAC Engine: Enforced in src/utils/rbac.js across 25 canonical database modules with zero static fallback permissions.
  • Manager Protection: DOM listeners intercept mutations, enforcing read-only oversight for manager roles.
Section 6

6. MySQL Database & Storage Architecture

  • Relational Persistence: Models for users, customers, staff, permissions, categories, subcategories, products, orders, order items, invoices, returns, and suppliers.
  • Snapshot SQL File: The root db.sql file provides full schema definitions and initial seeded records.
  • Query Splitting: Configured with QuerySplittingBehavior.SplitQuery to eliminate Cartesian duplication in multi-table joins.
  • Persistent Storage: Physical uploaded files live in Honeywell-Backend/wwwroot/uploads/, mounted to Docker as volume uploads:/app/wwwroot/uploads.
Section 7

7. Product Catalog & Cart Data Flow

  • Catalog API: Products, categories, and dynamic specifications loaded via REST endpoints.
  • Cart Context: Managed via CartContext.jsx, persisting selections to honey-well-cart in localStorage.
  • Price Visibility: Mode A (Catalogue Mode) suppresses prices and cart controls for institutional quote generation; Mode B (E-Commerce Mode) enables full checkout.
Section 8

8. Checkout & Order Lifecycle

  1. Customer provides shipping address and payment method in Checkout.jsx.
  2. Frontend calls orderService.create(), generating a unique Order ID in the backend.
  3. Backend inserts order records, line items, and decrements available product stock in the database.
  4. Order fulfills through lifecycle states: Pending Verification → Processing → Dispatched → In Transit → Delivered.
Section 9

9. Payment Architecture

Managed in PaymentController.cs:

  • UPI: VPA collection and status resolution.
  • Dynamic UPI QR: Real-time QR generation with active client-side transaction status polling.
  • Cards & Netbanking: Simulated 3D Secure and Net Banking OTP authentication.
  • Manual Bank Transfer: Corporate bank transfer details displayed; customer submits UTR number for manual approval in admin payments ledger.
  • Cashfree Note: Cashfree gateway SDK is not integrated in this codebase; operations utilize native simulation and UTR verification.

Section 13

13. Deployment Topology & Reverse Proxy

Configured in nginx.conf:

  • Reverse proxies /api/ and /uploads/ to backend container on port 5000.
  • Supports up to 550MB upload payloads (client_max_body_size 550m) for firmware binaries.
  • SPA client routing fallback via try_files $uri $uri/ /index.html.
Section 14

14. Limitations & Scope Summary

Verified Implementation: All features described above correspond to confirmed source code in the Honeywell Products repository. Third-party payment gateways (such as Cashfree) and external logistics carrier webhooks are not implemented in this version.
