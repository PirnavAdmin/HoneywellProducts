1. Architecture Overview & Monorepo Topology

The Honeywell Products platform is an enterprise e-commerce, quotation, and operations management platform specialized for commercial surveillance hardware, high-definition IP cameras, NVR/DVR units, solar-powered perimeter monitoring kits, and industrial cabling accessories.

5. API Integration & Request-Handling Approach

  • Dynamic Token Injection: adminToken (sessionStorage) or customerToken (localStorage) injected into Authorization: Bearer <token>.
  • Ngrok Tunnel Bypass: Requests include ngrok-skip-browser-warning: true to avoid tunnel warning pages.
  • DTO Normalization: Services convert null nested collections into safe default arrays or empty objects.
  • Cache-Control Invalidation: Real-time endpoints enforce Cache-Control: no-cache, no-store to prevent stale client badges.

7. MySQL Database & Storage Architecture

  • Relational Store: MySQL 8.0+ (database: honeywell_products) with complete models for users, customers, staff, permissions, categories, products, orders, invoices, returns, and suppliers.
  • Schema Snapshot: db.sql at the root provides structure and seed data.
  • Split Queries: EF Core QuerySplittingBehavior.SplitQuery avoids Cartesian product on nested joins.
  • Physical Media: Uploads hosted in Honeywell-Backend/wwwroot/uploads/, mounted to Docker as volume uploads:/app/wwwroot/uploads.

8. Product Catalog & Shopping Cart Data Flow

  1. Catalog Fetch: productService.getAll() retrieves products with specs, categories, and prices.
  2. Reactive Cart: CartContext.jsx manages item state and synchronizes with honey-well-cart in localStorage.
  3. Price Visibility: When Catalog Mode is active, prices are hidden and quote request buttons replace cart checkout.

9. Checkout & Order Processing Flow

  1. Address & Validation: Customer details checked via validators.js.
  2. Creation: POST /api/Orders generates Order ID, records line items, and decrements stock.
  3. Fulfillment Pipeline: Pending Verification → Processing → Dispatched → In Transit → Delivered.

11. B2B Procurement & RMA Returns Lifecycle

B2B Procurement

  1. Warehouse manager files Purchase Indent (PI).
  2. Procurement admin approves indent and issues Purchase Order (PO) to registered supplier.
  3. Supplier dispatches goods; warehouse logs received items and increments inventory in StockController.

RMA Returns

  1. Customer submits return request via POST /api/Returns.
  2. Admin reviews ticket in /admin/returns via ReturnsAdminController.
  3. Admin approves return, inspects unit, and issues replacement or refund.

15. Docker Multi-Container & Nginx Deployment

server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;
    client_max_body_size 550m;

    location /api/ {
        proxy_pass http://backend:5000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /uploads/ {
        proxy_pass http://backend:5000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
